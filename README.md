# 晓苌安餐饮巡检管理系统

面向餐饮连锁门店的三级巡检管理平台，将线下检查问题转化为线上闭环追踪，帮助一线厨师长高效完成逐项自查、帮助店长及时掌握门店卫生与服务质量、帮助总部稽查员与管理层通过数据看板洞察全局。

---

## 系统能力概览

系统以 **巡检任务 → 问题发现 → 待办生成 → 整改闭环 → 数据分析** 为主线，覆盖从门店自查到总部抽查的完整巡检链路：

1. **任务分发**：管理员或总部稽查员按门店创建巡检任务，支持三种任务类型——周检（厨师长日常自查）、月检（店长月度深度检查）、总部稽查（总部飞行检查）。创建时自动生成检查项目模板快照，确保检查标准版本可追溯。
2. **逐项填报**：执行人按检查项目模板逐项勾选通过 / 不合格，支持拍照留证（标记为必须拍照的检查项强制拍照），所有检查项按分类树形分组展示，填报进度实时可见。
3. **问题自动流转**：不合格项自动生成问题记录，按问题等级（红线 / 重要 / 一般）和门店自动创建整改待办，同时同步至飞书待办列表。
4. **整改闭环**：责任人在待办列表完成整改并上传整改照片，店长或稽查员审核确认后问题关闭；超时未整改自动触发提醒与升级通知。
5. **数据汇总**：工作台按角色展示个性化待办概览，AI 自动生成巡检周报与趋势分析，数据看板提供多维度可视化对比。

## 功能模块

### 工作台

登录后的首页面板，按角色展示个性化数据：

- **核心指标卡片**：待办数量、问题趋势、整改完成率等关键数字概览。
- **待办任务列表**：当前用户需处理的整改 / 确认任务，点击直达详情。
- **AI 分析摘要**：本周巡检趋势、高频问题、根因分析与改进建议。

### 巡检任务

管理巡检任务的全生命周期，支持三种任务类型与实时进度追踪：

| 功能 | 说明 |
|------|------|
| 任务列表 | 按门店、类型（周检/月检/总部稽查）、状态筛选查看 |
| 创建任务 | 为指定门店生成巡检任务，支持批量门店选择 |
| 巡检填报 | 按检查项目模板逐项勾选，附带照片与备注；必拍检查项强制拍照 |
| 任务归档 | 查看已完成的历史任务记录 |

**巡检类型**：
- **周检**：厨师长每周日常自查，覆盖高频基础检查项。
- **月检**：店长月度深度检查，覆盖更全面的检查项。
- **总部稽查**：总部稽查员飞行检查，发现问题可标记更高等级并直接生成追踪待办。

**检查项目模板体系**：
- 采用三层分级结构（一级系统 → 二级系统 → 三级检查项），树形分类管理。
- 每个检查项可配置标准说明、操作指引、是否强制拍照。
- 任务创建时自动生成模板快照（`templateSnapshot`），保证检查项版本可追溯。
- 支持软删除与回收站机制，误删可恢复。

**照片证据链**：
- 巡检填报时可对不合格项拍摄现场照片。
- 整改执行时上传整改后照片。
- 问题详情页集中展示问题照片与整改照片对比，形成完整证据闭环。

### 问题管理

巡检不合格项的追踪与整改，全程可追溯、可量化：

| 功能 | 说明 |
|------|------|
| 问题列表 | 按门店、等级、状态、分类、类型多维度筛选 |
| 问题详情 | 查看问题完整信息、整改记录、照片对比与时间线 |
| 问题分配 | 将问题指派给具体责任人 |
| 整改执行 | 责任人上传整改说明与照片，提交确认 |
| 整改确认 | 店长 / 稽查员审核整改结果，通过后问题关闭 |
| 问题归档 | 查看已关闭的历史问题 |

**问题等级体系**：
- **红线问题**：严重违规，需立即整改，超时自动升级通知。
- **重要问题**：需限期整改，临期自动提醒。
- **一般问题**：常规改进项，纳入日常整改流程。

**飞书待办集成**：
- 问题生成时自动创建飞书待办任务，责任人在飞书中即可查看和处理。
- 整改完成后双向同步状态，飞书待办自动标记完成。
- 待办默认 3 天期限，可在问题分配时调整。

### 数据看板

多维度数据分析与可视化：

- **门店数据总览**：各门店问题数量、整改率、排名对比。
- **趋势分析**：周 / 月维度的问题发现趋势曲线。
- **问题分布**：按检查分类、问题等级、门店分布的饼图与柱状图。
- **个人数据**：执行人的巡检完成情况与整改效率统计。

### 基础数据

系统基础信息维护（管理员 / 总部稽查员可见）：

| 模块 | 说明 |
|------|------|
| 门店管理 | 门店信息增删改查，关联店长、厨师长、执行店长 |
| 检查分类管理 | 检查项目的树形分类结构维护 |
| 检查项目管理 | 按类型（周检 / 月检）管理检查项模板，支持启用 / 禁用 |

### 工作流配置

自动化任务与通知调度（管理员可见）：

- 定时巡检任务自动生成（支持 Cron 表达式）。
- 问题超时提醒与升级通知。
- 整改临期飞书消息推送。

### AI 智能分析

系统内置 AI 分析引擎，基于巡检数据自动生成多维度洞察报告，帮助管理者从数据中发现规律、定位问题：

| 洞察类型 | 说明 |
|----------|------|
| 趋势分析（trend） | 自动分析巡检问题的周/月趋势，识别上升或下降的变化信号 |
| 根因分析（root_cause） | 对高频问题自动追溯根本原因，给出改进建议 |
| 门店匹配（store_matching） | 对比不同门店的问题模式，发现共性薄弱环节 |
| 案例挖掘（case_mining） | 从历史问题中提取典型案例，形成培训素材 |
| 个人成长（personal_growth） | 追踪个人巡检效率与整改质量的变化趋势 |

AI 分析结果在工作台首页以卡片形式展示，并可根据角色和门店自动定向推送。

### 成就与激励体系

通过徽章和称号激励一线人员持续提升巡检质量与整改效率：

**徽章（Badge）**：

| 徽章 | 获取条件 |
|------|----------|
| 细节侦探 | 单次巡检发现问题数 ≥ 3 个 |
| 周检速度之星 | 周检提交时间排名前 20% |
| 月检速度之星 | 月检提交时间排名前 20% |
| 连续打卡 | 连续完成巡检任务 |
| 改进达人 | 累计整改完成数 ≥ 10 个 |

**称号（Title）**：根据综合表现授予荣誉称号，在个人数据页面展示。所有成就按半年周期统计，新周期自动重新计算。

### 智能通知与自动化

工作流引擎驱动的事件通知体系，确保问题不遗漏、不超时：

| 通知类型 | 触发条件 |
|----------|----------|
| 任务分配通知 | 新巡检任务分配后即时推送 |
| 问题指派通知 | 问题指派给责任人时推送 |
| 临期提醒 | 整改期限前 1 天自动提醒 |
| 超时升级 | 超时未整改自动通知上级管理者 |
| 整改完成通知 | 整改确认通过后通知相关人员 |

所有通知通过飞书消息推送，发送记录存入 `notification_log` 表，支持追溯和故障排查。通知规则在工作流配置中按门店、任务类型、检查模块灵活组合。

## 使用指南

### 厨师长（一线巡检）

1. 登录后在工作台查看**待办任务**卡片，点击进入巡检填报。
2. 按检查项目**逐项勾选**（通过 / 不合格），不合格项拍照并填写备注。
3. 提交后系统自动生成问题记录和整改待办。
4. 在问题管理中跟踪已提交问题的**整改进度**。
5. 收到整改待办后，完成整改并**上传照片**、提交确认。

### 店长（门店管理）

1. 工作台查看本店**待办概览**：待整改问题数、临期问题等。
2. 在问题管理中将问题**指派给对应责任人**（厨师长或执行店长）。
3. 定期查看数据看板，关注本店**整改率与问题趋势**。
4. 收到责任人提交的整改后，审核确认或驳回重新整改。

### 总部稽查员（抽查与管理）

1. 在巡检任务中**创建总部稽查任务**，面向全部门店或指定门店。
2. 执行稽查填报，发现红线问题按**等级标记**并生成追踪待办。
3. 在数据看板中查看**全部门店排名与对比**，定位薄弱门店。
4. 维护基础数据中的**检查分类与检查项目模板**。

### 管理员（系统管理）

1. 在基础数据中维护**门店信息**、分配门店关联角色。
2. 管理**检查项目模板**，按需启用 / 禁用检查项。
3. 在角色管理中为人员**分配系统角色**。
4. 配置**工作流**：设置定时任务自动生成巡检任务、逾期提醒、模块级通知规则等，支持 Cron 表达式精确控制执行时间。

## 快速开始

### 环境要求

- Node.js >= 22.0.0
- PostgreSQL 数据库

### 本地开发

```bash
# 安装依赖
npm install

# 启动前端开发服务器
npm run dev:client

# 启动后端开发服务器
npm run dev:server
```

前端默认运行在本地开发端口，后端 API 通过代理转发。开发环境已内置用户认证与角色切换能力。

### 部署

应用基于飞书妙搭平台构建，通过 `lark-cli` 完成部署与发布：

```bash
# 部署到线上环境
npx lark-cli apps +release-publish
```
